# 技术方案 —— B站合集字幕提取器（MVP）

> 版本：v0.1　日期：2026-08-30
> 关联文档：[产品设计文档](./产品设计文档.md)（下称"产品文档"）

## 1. 技术选型

| 层面 | 选择 | 版本要求 | 理由 |
| --- | --- | --- | --- |
| 语言 | Python | ≥ 3.10 | B站接口的社区经验（wbi 签名等）几乎都在 Python/JS 生态；3.10 起可用 `match`、更好的类型标注 |
| HTTP 客户端 | httpx | ≥ 0.27 | API 与 requests 同构，自带更清晰的超时/重试控制；保留 async 能力，将来提速时无需换库 |
| CLI | typer | ≥ 0.12 | 三个参数的场景下获得类型化的参数定义和友好的 `--help`；若追求零依赖可退回 `argparse`，接口不变 |
| 数据模型 | pydantic v2 | ≥ 2.7 | 接口响应的解析与校验集中声明，字段变化时改一处即可 |
| 测试 | pytest | ≥ 8.0 | fixture 加载、marker 分组（常规测试 / 手动集成测试）都很顺手 |

运行时依赖仅 4 个：`httpx`、`pydantic`、`typer`（及其附带的 `click`）。不引入数据库、消息队列、前端。

### 1.1 为什么不用 Celery + Redis（结论备忘）

- 本工具是**单机本地 CLI**：一条命令进，一批 Markdown 出，没有常驻服务和异步消费方，任务队列没有存在场景。
- 产品文档明确要求**串行 + 随机间隔**防风控，一个 `for` 循环 + sleep 就是全部的调度逻辑；引入 Celery 反而把"刻意限速"变成需要绕行实现的负担。
- 失败处理（单集失败不中断、结尾汇总、重跑靠增量跳过）用 try/except + 状态枚举即可覆盖；且 Celery 的自动重试机制会加剧触发风控，是有害的。
- 何时重新考虑：后续做成多用户 Web 服务、或引入 ASR 这类分钟级重任务需要后台队列时。届时也先评估更轻的方案（`asyncio.Semaphore` 限并发、FastAPI BackgroundTasks），Celery 不是第一选择。

## 2. 总体架构

四层单向依赖，转换层是纯函数（无 I/O、无网络），接口层是唯一接触网络的模块：

```
┌─────────────────────────────────────────────┐
│ cli.py        参数解析、退出码                │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│ pipeline.py   编排：解析输入 → 分集列表 →      │
│               逐集取字幕 → 落盘 → 汇总        │
└──────┬───────────────────────┬──────────────┘
       │                       │
┌──────▼──────────────┐ ┌──────▼──────────────┐
│ bilibili/  接口层    │ │ converter.py 转换层 │
│ wbi 签名、限速、重试  │ │ 字幕JSON→Markdown   │
│ (唯一 I/O 边界)      │ │ (纯函数)            │
└─────────────────────┘ └─────────────────────┘
       │                       ▲
┌──────▼──────────────┐        │
│ storage.py          │────────┘
│ 文件名清洗、落盘、增量 │
└─────────────────────┘
```

产品文档要求"架构预留平台抽象接口"，用 `typing.Protocol` 定义，不做重量级 ABC：

```python
class PlatformClient(Protocol):
    def resolve_input(self, raw: str) -> str: ...        # URL或ID → season_id
    def list_episodes(self, season_id: str) -> list[Episode]: ...
    def fetch_subtitles(self, episode: Episode) -> SubtitleTrack | None: ...
```

MVP 只写 `BilibiliClient` 实现；未来加平台 = 新增一个实现类 + pipeline 侧一个工厂分支。

## 4. 数据模型

```python
class Episode(BaseModel):
    bvid: str
    cid: str | None        # 取字幕前需补齐，见 §5.2
    title: str
    index: int             # 合集内序号，从 1 开始

class SubtitleLine(BaseModel):
    from_time: float
    to_time: float
    content: str

class SubtitleTrack(BaseModel):
    lan: str               # 如 zh-CN / ai-zh
    lines: list[SubtitleLine]

class EpisodeStatus(StrEnum):
    SUCCESS = "success"        # 新下载成功
    SKIPPED = "skipped"        # 文件已存在，增量跳过（汇总时计入成功组并单独标注）
    NO_SUBTITLE = "no_subtitle"
    FAILED = "failed"          # 网络错误 / 风控 / 解析失败，带 reason

class EpisodeResult(BaseModel):
    episode: Episode
    status: EpisodeStatus
    reason: str | None
```

内部用四态，对外汇报折叠为产品文档的三类：成功（含 SKIPPED）/ 无字幕 / 失败。

## 5. B站接口设计

> **以下端点与字段均来自社区文档（bilibili-API-collect）的当前认知，动手前按 M0 实测清单（§10）逐一验证，以实测为准。** 接口细节全部封在 `bilibili/` 内，变动时只改这一层。

### 5.1 接口清单

| 用途 | 端点（GET） | 关键入参 | 关键出参 |
| --- | --- | --- | --- |
| 分集列表（分页） | `https://api.bilibili.com/x/polymer/web-space/seasons_archives_list` | `season_id`, `page_num`(从1), `page_size`(≤100) | `data.meta.name`, `data.archives[]`(bvid,title), `data.page.total` |
| 单视频 cid | `https://api.bilibili.com/x/player/pagelist` | `bvid` | `data[].cid`（备选：`/x/web-interface/view`，实测后取轻量者） |
| 字幕列表 | `https://api.bilibili.com/x/player/wbi/v2` | `bvid`, `cid`，需 Cookie | `data.subtitle.subtitles[]`(lan, lan_doc, subtitle_url) |
| wbi 密钥 | `https://api.bilibili.com/x/web-interface/nav` | 无需登录 | `data.wbi_img.img_url/sub_url` |

字幕 JSON 直接从 `subtitle_url`（hdslb.com 域）下载，结构预期为 `{"body":[{"from","to","content"}]}`。

### 5.2 wbi 签名

1. 从 nav 接口取 `img_url`/`sub_url` 的文件名（去扩展名）得 `img_key`、`sub_key`，拼接成 64 字符。
2. 按 FIXED 混淆表（社区维护，写死在 `wbi.py`）重排，取前 32 位得 `mixin_key`。
3. 对请求参数追加 `wts`（当前秒级时间戳），参数名排序，参数值过滤 `!'()*` 字符，URL 编码后与 `mixin_key` 拼接做 md5，得 `w_rid`；最终请求带上 `w_rid` + `wts`。

nav 密钥进程内缓存即可（会话级），无需持久化。签名函数设计为纯函数 `sign(params: dict, img_key, sub_key, wts) -> dict`，用固定输入输出向量做单元测试。

### 5.3 请求头与 Cookie

- 固定 `User-Agent`（真实浏览器 UA）+ `Referer: https://www.bilibili.com/`，两者缺失是常见 412 成因。
- Cookie 仅来自 `--cookie` 参数或 `BILI_COOKIE` 环境变量（产品文档 §3），整串透传到 API 域请求；不落盘、不进日志。

### 5.4 限速与风控对策

| 项 | 策略 |
| --- | --- |
| 并发 | 全程串行（MVP 不做并发，见 §1.1 的提速备注） |
| 间隔 | 分页/列表类请求随机 0.5~1.5s；player/字幕类请求随机 1.5~3s |
| 重试 | 指数退避 2s/4s/8s + 抖动，最多 3 次；仅对网络错误和风控信号（HTTP 412/429、业务码 -352/-412）重试 |
| 风控升级 | 退避后仍风控 → 当前分集标记 FAILED，**继续下一集**，不中断整体；连续 N 集（默认 5）风控则提前终止并提示等待后重跑 |
| 预估耗时 | 每集约 3 个请求（pagelist + player + 字幕 JSON），50 集合集 ≈ 2~4 分钟，可接受 |

## 6. 核心流程

```
resolve_input(raw)                     # 见下
  └─ list_episodes(season_id)          # 翻页取全量，得到 meta.name + episodes[]
       └─ for ep in episodes:
            1. 增量判断：storage.output_path(...) 已存在且非空 → SKIPPED，continue
            2. pagelist 拿 cid（失败重试后仍失败 → FAILED）
            3. player/wbi/v2 拿字幕列表；空 → NO_SUBTITLE
            4. 选轨：zh-CN（人工CC）> ai-zh > 列表第一个；下载 JSON（失败 → FAILED）
            5. converter.subtitle_to_markdown(title, lines) → 纯字符串
            6. storage.write_markdown(...) 落盘 → SUCCESS
       └─ 汇总打印三类清单；存在 FAILED 时退出码 1，否则 0
```

**输入解析规则**（`resolve_input`）：

- 纯数字 → 直接作为 season_id。
- URL 中含 `sid=` 或 `season_id=`（如 `space.bilibili.com/{mid}/channel/collectiondetail?sid=123`）→ 提取该值。
- 其余（含裸 BV 号）→ 报错退出，提示仅支持合集链接（产品文档非目标）。

**文件名规则**（`storage.py`）：

- 模板：`EP{index:02d} {title}.md`，目录 `<output>/<合集名>/`。
- 清洗：`<>:"/\|?*` 替换为 `_`，去除尾部空格和 `.`，剔除/改写 Windows 保留名（CON、PRN、AUX…）。
- 长度：标题截断至 60 字符，保证整路径远低于 260 限制。
- 落盘：`encoding="utf-8"`、`newline="\n"`，`open(..., "x")` 前置存在性检查实现增量。

## 7. 转换层设计

唯一入口，纯函数、确定性、无 I/O：

```python
def subtitle_to_markdown(title: str, lines: list[SubtitleLine]) -> str
```

段落拼接启发式（v1，刻意简单，后续迭代打磨）：

1. 顺序累积字幕行到当前段落；行文本先做空白归一化（去首尾空格、合并连续空格）。
2. **闭合段落条件**（满足其一）：段长 ≥ 80 字符且当前行以句末标点（。！？…）结尾；或当前行与上一行的起点间隔 > 2.0 秒（说话停顿）。
3. 标题永远作一级标题；段间空行分隔。

该函数所有行为用离线 fixture 单测锁定，不含任何网络与随机性。

## 8. 结果汇总与退出码

结尾输出（对齐产品文档三类）：

```
—— 汇总 ——
成功 45（其中增量跳过 40）
无字幕  3：EP12（AI字幕未生成）、EP17、EP33
失败    2：EP08（HTTP 412，疑似风控）、EP25（字幕下载超时）
失败可重跑：subtitle-cli <同一输入> 会自动跳过已成功分集
```

- 退出码：`0` 无失败（含全部成功/跳过/无字幕）；`1` 存在失败；`2` 参数/输入错误。
- `--cookie` 的值不出现在任何输出与异常信息中。

| 单元测试（默认跑） | converter 段落规则/空字幕/超长行；wbi 签名固定向量；resolve_input 各 URL 形态与报错；storage 文件名清洗/保留名/增量跳过 | 否，全部用 `tests/fixtures/` 录制响应 |
