# 页面结构与交互设计 —— Obsidian 知识库版（v1）

> 版本：v0.1（设计稿，待确认）　日期：2026-08-30
> 上游文档：`docs/产品设计文档.md`（本期增补需求：直接写入 vault、属性头 + 合集索引页、旧字幕迁移）

## 1. 设计目标

在现有单页卡片流（提取设置 → 运行进度 → 结果汇总 → 审查报告 → 生成文件 → 预览）之上做**增量改造**：

1. 「输出位置」从单一目录升级为 **Obsidian vault（默认）/ 普通文件夹** 二选一；
2. 新增**迁移旧字幕**入口（不联网）；
3. 进度、汇总、文件列表、预览围绕「写入 vault 的笔记 + 索引页」补充反馈；
4. 命令行同步获得 `--vault` 与迁移子命令，行为与网页一致。

原则：演示模式保持现状（离线、不需要 vault），首次体验路径不被打断；真实模式默认 vault。

## 2. 通用设计：vault 配置与记忆

- **vault 路径**与 **vault 内字幕文件夹**（默认 `B站字幕`）两项配置，保存在本地配置文件 `~/.subtitle-cli/config.json`；网页启动时读取回填，用户修改后即保存。CLI 读取同一文件（命令行参数优先于配置文件）。
- 输出最终目录：`<vault>/<字幕文件夹>/<合集名>/`，与现有 `<output>/<合集名>/` 结构对齐。
- **「检查 vault」按钮**（与「检测登录态」并列的轻量自检），三种结果：
  - ✅ 可写，是有效的 vault 根目录（找到 `.obsidian` 文件夹）；
  - ⚠️ 可写，但没找到 `.obsidian`——可能选的是 vault 子目录，仍可写入，但「在 Obsidian 中打开」链接不可用；
  - ❌ 路径不存在/不可写——提供「创建该文件夹」动作，创建后需重按检查。
- 不强制通过检查才能提取，但路径不存在时「开始提取」直接报错阻止。

## 3. 网页页面结构（自上而下）

### 3.1 提取设置（改造）

```
┌─ 提取设置 ───────────────────────────────────────────┐
│ ( ) 离线演示（内置 Mock，无需 Cookie）                │
│ (•) 真实接口（需登录 Cookie）                        │
│                                                     │
│ 合集页 / 合集内任一视频链接 / BV 号 / season_id       │
│ [____________________________________]              │
│                                                     │
│ Cookie（真实接口时显示，含「检测登录态」）—— 不变     │
│                                                     │
│ 输出位置                                             │
│ (•) 写入 Obsidian vault（推荐）  ( ) 输出到普通文件夹 │
│                                                     │
│ vault 路径        [D:/Obsidian/MyVault_] [检查 vault]│
│                   ✅ 可写，有效的 vault 根目录        │
│ vault 内字幕文件夹 [B站字幕_]                        │
│ （选中「普通文件夹」时，此区域换回原「输出目录」输入） │
│                                                     │
│ [开始提取]  [预览第 1 集（审查排版与内容）]  ⏳ …     │
└─────────────────────────────────────────────────────┘
```

- 演示模式下隐藏整个「输出位置」区块，维持演示写到 `demo_output/` 的现状。
- vault 路径为空时点「开始提取」：输入框标红聚焦，提示「先填写 vault 路径，或切换到普通文件夹输出」。

### 3.2 迁移旧字幕（新增卡片，位于提取设置下方）

```
┌─ 迁移旧字幕（不联网、不需要 Cookie）─────────────────┐
│ 把已下载的旧字幕文件夹转换成带属性头的笔记写入 vault。 │
│ 恢复不了的字段（BV 号、视频链接）将留空并在报告中说明。│
│                                                     │
│ 旧字幕目录  [D:/…/字幕/output_]        [扫描旧合集]  │
│                                                     │
│ ☑ 示例合集·美食漫谈（6 个文件）                      │
│ ☐ 另一个旧合集（45 个文件）                          │
│                                                     │
│ [ ] 覆盖已迁移过的文件（默认跳过已含属性头的笔记）    │
│                                                     │
│ [开始迁移]   目标：上方配置的 vault                  │
└─────────────────────────────────────────────────────┘
```

- 扫描逻辑：旧目录下每个含 `.md` 的子文件夹视为一个合集；散落的单文件不在此处理范围（报告说明）。
- 「已迁移」的判定：笔记文件顶部已存在本工具写入的 frontmatter（含 `fetched_by: subtitle-cli` 标记）。
- 迁移与提取共用同一套「运行中」互斥锁：任一任务运行时，另一个入口按钮禁用。

### 3.3 运行进度 / 结果汇总（扩展）

- 进度日志沿用现有逐行着色，新增两类行：
  - `已写入 vault：EP01 第一集标题.md`（正常写盘行）；
  - `索引页已更新：《合集名》.md（45 集）`（每次运行结束前一行）。
- 汇总文本新增一行落点信息：
  `已写入 vault：D:/Obsidian/MyVault/B站字幕/《合集名》/`
- 汇总卡片新增按钮 **「在 Obsidian 中打开合集索引」**：使用 `obsidian://open?vault=<vault名>&file=<字幕文件夹>/<合集名>/<合集名>` URI；vault 检查为 ⚠️/❌ 时隐藏该按钮。

### 3.4 生成的文件 / 预览（扩展）

- 文件列表：**索引页固定排第一并默认选中**，其后按 EP 序号排列；每个文件带小徽标（`新写入` / `跳过` / `迁移`）。
- 预览渲染视图：YAML 属性头渲染为 Obsidian 风格的属性表（键值两列），不出现在正文里；「查看原文」显示含 YAML 的完整 Markdown。
- 预览渲染视图里的**双链可点击**：点击 `[[EP01 …]]` 等价于点文件列表对应按钮，在预览区打开该集（仅本地预览行为，不影响写盘内容）。
- 「预览第 1 集」的预览稿也按新格式生成（含属性头），审查报告新增一行「属性头字段完整性」。

## 4. 核心交互流程

### 4.1 首次使用（真实模式）

填来源 → 粘贴 Cookie →「检测登录态」→ 填 vault 路径 →「检查 vault」（✅）→「预览第 1 集」确认排版 →「开始提取」。vault 路径保存后，下次打开网页自动回填，日常只需两步：贴链接 → 开始提取。

### 4.2 提取流程（增量语义）

1. 分集文件已存在 → 跳过（现状不变）；
2. 索引页**每次运行都重新生成**：扫描该合集文件夹里当前全部分集笔记（含历史跳过的），保证索引与实际文件一致；
3. 写盘失败的单集按现有规则计为「失败」，不中断；索引页只收录成功落盘的笔记。

### 4.3 迁移流程

扫描 → 勾选合集 → 开始迁移 → 逐文件进度（`转换 / 跳过（已迁移）/ 失败（原因）`）→ 结束时同样更新索引页并给「在 Obsidian 中打开」→ 汇总三分类：迁移成功 / 跳过 / 失败。迁移不访问网络；BV 号、视频链接留空，合集名与集数从文件名与一级标题解析，解析失败的文件计入失败清单。

### 4.4 失败与边界

| 情形 | 行为 |
| --- | --- |
| vault 路径不存在 | 开始/迁移前直接报错，指向「检查 vault → 创建文件夹」 |
| vault 中途不可写（盘符拔出等） | 该集计为失败带原因，其余继续，结尾汇总 |
| 合集名含 Windows 非法字符 | 沿用现有清洗规则，清洗结果同步用于索引页双链 |
| 旧笔记已是新格式 | 迁移默认跳过；勾选「覆盖」则重写（正文仍一字不动，仅重算属性头/索引） |
| `/api/file` 越权读取 | 现有目录穿越防护同样作用于 vault 目录 |

## 5. 笔记格式（网页预览与落盘一致）

### 5.1 分集笔记

```markdown
---
title: 第1集 视频标题
collection: 合集名
season_id: "12345"        # 多P 视频无此字段
bvid: BV1xxxxxxxx
episode: 1
url: https://www.bilibili.com/video/BV1xxxxxxxx
fetched_at: 2026-08-30
fetched_by: subtitle-cli
tags:
  - B站字幕
  - 合集名
---

# 第1集 视频标题

正文段落……（与现有转换结果完全一致，一字不动）
```

键名用英文（Obsidian 属性面板与 Dataview 等插件兼容性最好），值保留中文。多P 视频的 `url` 追加 `?p=<序号>`。

### 5.2 合集索引页（文件名 `<合集名>.md`，置于合集文件夹内）

```markdown
---
type: index
collection: 合集名
season_id: "12345"
episodes: 45
updated: 2026-08-30
tags:
  - B站字幕
  - 索引
---

# 合集名

- [[EP01 第一集标题|第1集 第一集标题]]
- [[EP02 第二集标题|第2集 …]]
- …
```

无字幕/失败的集不进索引，但索引页重生成时会收录文件夹里已有的全部分集笔记。

## 6. 命令行交互

```bash
# 提取并写入 vault（--vault 优先于配置文件；缺省子文件夹 B站字幕）
subtitle-cli <来源> --vault "D:/Obsidian/MyVault"
subtitle-cli <来源> --vault "D:/Obsidian/MyVault" --vault-subdir "学习/B站字幕"

# 不带 --vault 时行为完全不变（--output 普通目录输出）
subtitle-cli <来源> --output D:/字幕/

# 迁移旧字幕（独立入口，避免破坏 subtitle-cli <来源> 的现有用法）
subtitle-cli-migrate "D:/…/output" --vault "D:/Obsidian/MyVault" [--overwrite] [--dry-run]
```

- `--dry-run`：只打印将要做的事（转换哪些、跳过哪些），不写盘；网页端暂不提供对应项（扫描列表已起预览作用）。
- 退出码沿用：0 无失败 / 1 存在失败 / 2 参数错误；迁移同样遵循。

## 7. 网页 API 增量（接口层示意）

| 端点 | 说明 |
| --- | --- |
| `GET /api/config` / `POST /api/config` | 读写 vault 路径、字幕文件夹（配置文件持久化） |
| `POST /api/check-vault` | 检查 vault：可写性 / `.obsidian` 存在性 / 可选创建 |
| `POST /api/migrate-scan` | 扫描旧目录 → 合集清单 + 各自文件数 |
| `POST /api/migrate` | 后台线程执行迁移，复用 `/api/run` 轮询与三分类汇总 |

`/api/extract` 增加可选参数 `vault`、`vault_subdir`；`/api/file` 的白名单目录按当前任务落点（vault 或普通目录）解析。

## 8. 暂不做（与上轮确认一致）

- Obsidian 插件、自动刷新 vault 内已打开的笔记；
- 迁移时联网补齐缺失字段（BV 号等）；
- 笔记模板自定义、双链以外的图谱增强；
- 弹窗选目录（仍为文本输入 + 自检按钮）。
